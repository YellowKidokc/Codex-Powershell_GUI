# BLOCK E — THE EPISTEMIC RAZOR
## Claim-by-Claim Verification Engine
## Use When You Need to Cut to Bone

---

# PURPOSE

This block subjects specific claims to ruthless verification. It strips rhetoric, isolates discrete assertions, and tests each one independently. Use it when you need to know what actually survives examination — not what sounds good, not what is commonly believed, not what is comfortable.

---

# PHASE 1: CLAIM EXTRACTION

Deconstruct the target text, argument, or position into a numbered list of discrete, isolated claims.

Rules:
- Strip all rhetorical formatting, adjectives, emotional language, and narrative momentum
- Each claim must stand alone — if removing it changes nothing else, it was decorative, not structural
- Identify hidden premises (things the argument assumes but does not state)
- Identify load-bearing claims (things that, if removed, collapse other claims downstream)
- Number everything. No claim escapes the list.

---

# PHASE 2: ADVERSARIAL VERIFICATION (THE FILTER)

Subject EVERY claim from Phase 1 to three verification passes:

### PASS A — Logical Structure
- Does the claim survive formal logic?
- Are there hidden premises or unstated assumptions?
- Does the conclusion actually follow from the premises, or does it require an inferential leap?
- Is there a non-sequitur disguised by rhetorical flow?
- Would the opposite conclusion be equally supported by the same premises?

### PASS B — Evidence Base
- Is this claim supported by primary sources (documents, data, original texts)?
- Is it supported only by secondary sources (interpretations, commentary, media)?
- Is it supported only by repetition (commonly stated but never traced to origin)?
- What is the TIER (T1-T5) of the evidence supporting this claim?
- **CONTAMINATION CHECK:** On suppressed or contested topics, is the "evidence base" itself potentially constructed? Can you trace the debunking/supporting evidence to its original source and verify its independence?

### PASS C — Source Integrity
- Does the evidence DIRECTLY support the claim, or does it require an interpretive bridge?
- Is the source independent, or does it trace back to a single origin point that got amplified?
- Does the source have a track record of accuracy on this type of claim?
- Does the source have structural incentives (funding, institutional affiliation, political alignment) that could bias its output?
- **ABSENCE CHECK:** Is there evidence that SHOULD exist but does not? Is the absence explained or unexplained?

---

# PHASE 3: CONTRADICTION & BRUTE FACT BINDING

For claims that pass the filter:
- Does this claim contradict any other surviving claim? If yes, both stay in the output with the contradiction flagged.
- Does this claim rely on a brute fact (an unexplained foundation it cannot justify)? If yes, name the brute fact explicitly.
- Does this claim rely on circular logic (A because B, B because A)? If yes, trace the exact loop.
- Does this claim require the absence of evidence to be treated as evidence of absence? If yes, flag it.

Do NOT attempt to resolve paradoxes or contradictions. State them. Let them sit. The human will decide what to do with them.

---

# PHASE 4: THE SLIM MARGIN OUTPUT

Deliver the report in this exact order:

### 1. VERIFIED CORE
The minimal list of claims that survived all three passes. Each one tagged with:
- The claim (plain language)
- Evidence tier (T1-T5)
- What it stands on
- What would break it

### 2. SURVIVED BUT STRAINED
Claims that passed but have identifiable weaknesses. Each one tagged with:
- Where the strain is
- What additional evidence would confirm or collapse it
- Current confidence level

### 3. EPISTEMIC GAPS
What is MISSING that prevents further verification. Be specific:
- What document, data point, or testimony would fill this gap?
- Has anyone attempted to fill it? What happened?
- Is the gap explainable (data simply doesn't exist) or suspicious (data should exist but doesn't)?

### 4. DISCARDED CLAIMS
Claims that failed the filter. Each one tagged with:
- Which pass it failed (A, B, or C)
- The exact reason for failure
- Whether the failure is repairable (could be rescued with new evidence) or terminal (logically impossible)

---

# STOP CONDITION

Do not summarize. Do not provide a comforting conclusion. Do not wrap up with "in conclusion" or "overall" or "the evidence suggests." End immediately after the Discarded Claims section.

The output is the output. It does not need a frame.

---

*This block is a scalpel. Use it when precision matters more than exploration. Combine with Block D (Research Workflow) Phase 5 for maximum rigor.*
